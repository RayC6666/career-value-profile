# 应用分支执行说明

## 共同行为

仅执行已选择分支。使用画像作为理解基础，原始资料与确认事实作为事实依据。开始时确认相关输入是否更新，已有信息不重复索要。按用途组织表达，不产生相互冲突的事实。工具和文件格式按环境能力及用户要求选择；未完成文件检查时说明范围。

## A. 简历优化

**输入：** 画像、事实与证据表、现有简历、目标岗位或方向。

**步骤：**
1. 确认读者和岗位用途。没有JD可做通用稿，但不声称已完成具体岗位匹配。
2. 需要岗位依据时先执行B的岗位要求分析，再作匹配，不用个人经历迁就岗位标准。
3. 建立职业价值主线：业务背景与责任 → 关键判断与能力 → 组织实现 → 业务及组织变化。四层在整段经历中完整即可，不机械要求每条齐全。
4. 优先完成通用内容核对，再按目标调整方向稿。用户已有明确专项需求时遵循其范围。每个代表项目承担明确证明任务，避免堆积无关联指标。
5. 选取有解释价值的商业和组织证据，说明实际个人作用；规模数据用于背景，不能冒充个人创造。团队独立承接等变化与商业成果均可支持价值。
6. 进行支持与质疑两种审查：是否值得约面、是否有个人判断、结果是否能支撑主张、权限与角色是否夸大。
7. 交付改稿与重要修改依据。缺失联系信息等在核对稿标注；投递前处理未决事项。需要正式文件时核对内容和排版，不默认一页或固定结构。

**表达检查：** 能力与价值应出现在简历正文，不只写在修改说明里。按事实选择简短主张，例如“记录口径判断与标准转化”，随后用关键判断和结果支撑；不能只把一段事件拆成三条动作，也不能把能力词放在无证据的标题上。必要背景只出现一次。共同的事实缺口和核对说明放在简历外的待核清单，正式正文保留准确贡献边界即可。

**输出：** 通用或指定方向简历、重点修改说明、影响使用的待核项。

**完成标准：** 读者能理解责任尺度、关键能力和贡献；事实来源一致；没有用形容词替代价值、用数字替代个人作用。

## B. 岗位匹配

**输入：** 原始JD或岗位材料、画像与证据表。

**步骤：**
1. 独立整理岗位目标、工作对象、关键任务和决策、结果责任、权限与协作、硬条件。
2. 形成关键能力要求，区分显式JD条件和分析推断。材料不足时限制结论；若需外部查找按用户授权及工具规则执行。
3. 对不同岗位先说明共性与核心差异，再处理企业特定要求，不拿一个样本代表整个方向。
4. 逐项连接个人证据，标记：已有直接证据、相邻可迁移且有条件、资料不足待验证、明确经验缺口。
5. 给出匹配依据、风险及验证办法；不以个人兴趣替代胜任条件，也不把经验缺口泛化成人格或能力缺陷。

**输出：** 岗位要求模型、匹配矩阵、关键风险和验证任务、简历表达重点。

**完成标准：** 要求与个人证据分开建立；每项判断有依据和边界；结论只覆盖实际分析对象。

## C. 职业发展

**输入：** 画像、当前意愿、希望改变的工作与责任、用户愿意讨论的条件。

**步骤：**
1. 区分已有能力、希望使用的能力、希望形成的新能力，明确未来责任变化。
2. 分析进入更复杂情境需要的判断、协作、资源或专业理解变化，不把全部问题归于缺少课程。
3. 对候选路径说明已有基础、需要形成的能力、所需实践机会和支持条件；无依据不预测成功概率。
4. 给出分阶段验证：具体实践任务、观察信号、反馈来源、继续或调整的条件。时间跨度按目标确定，不虚设升职期限。
5. 由用户选择投入方向；第二曲线、转型或管理路径仅在有相应目标时讨论。

**输出：** 路径比较或阶段发展方案，每条建议含目标变化、实践载体、反馈与验证。

**完成标准：** 建议对应实际能力变化和未来责任，不以“多学习、多积累”收尾，不代用户作出职业承诺。

## D. 面试准备

**输入：** 具体JD、当前简历、画像及证据、用户选择的训练方式。

**步骤：**
1. 核对岗位与材料版本。明显责任范围或硬条件差距先说明，确认是否继续挑战性推演。
2. 建立问题覆盖：动机、经历主线、岗位核心能力、成果、方法、失败复盘、协作冲突、期望及反问；顺序与轮数按岗位和用户需求调整。
3. 选择用户亲答训练或助手模拟拟答，并明确两者区别。不得把助手拟答的表现当成用户真实能力。
4. 提问 → 回答 → 基于回答评审 → 追问或下一轮；评审后改写另列，不覆盖原答。只用事实资料作答，情境建议明确标注，不补成过去经历。
5. 评审检验判断、取舍、贡献、结果与岗位联系，承认证据不足；不以索要更多数字代替分析。
6. 交付强证据、主要风险、需重写回答、待补信息与后续训练重点。若使用评分，先定义维度与标尺；未覆盖不打分，不跨不同JD简单排名。

**输出：** 案例库、训练或推演记录、复盘和改写建议。

**完成标准：** 能区别真实经历、假设思路与表达建议；用户理解哪些已得到支持、哪些需要真实作答或补充材料验证。

## 反馈回流

真实反馈可触发定向修订，但一次面试结果不能推翻整个能力画像。新增资料先登记并转Markdown；事实更新后检查受影响的画像和应用版本。用户更换话题时停止当前推演，不自行续接。
