# 私有项目记录模板

这些模板仅在使用者的私有工作区实例化，不写入技能目录。按需建立；已有信息由助手预填，未知保留，不重复索要。

### 目标约定卡
当前问题｜期望用途｜希望得到的成果｜暂不处理｜当前偏好与条件｜确认状态。

### 资料与转换清单
资料编号｜原件引用｜类型｜时间范围｜转换件引用｜转换状态｜覆盖检查｜缺失内容及影响｜处理决定。

### 经历卡
时期｜业务情境｜本人角色与权限｜关键问题｜判断与取舍｜本人和他人的行动｜变化与口径｜来源｜不确定项。

### 能力证据卡
能力或价值主张｜代表行为｜关联经历｜支持证据｜反例或替代解释｜适用条件｜成长变化｜确认状态。

### 待确认问题卡
当前理解｜缺口或冲突｜为何影响结论｜已检查材料｜用户可补充内容｜记不清时的替代分析方式。

### 项目状态卡
当前目标｜阶段｜已确认节点及范围｜用户纠偏｜最新有效产物｜未决事项｜下一步。

确认记录补充：节点｜针对的材料或产物版本｜实际确认内容｜保留未知｜明确回复｜仍有效/部分需重核。不要记录不存在的确认；示例回复和测试夹具不得作为真实用户授权。

### 应用成果内部追溯表

成果与版本｜关键句或主张｜对应事实/能力证据｜来源定位｜确认状态｜哪些输入改变时需要重核。

用于检查画像、简历和面试材料的一致性，不必把内部证据表全部放入正式投递稿。事实更正后按此表定位受影响内容。

由助手先根据材料填写已有信息，不让使用者重复录入。无文件用户也可用口述和时间线启动；资料少时控制结论范围，不设资料数量门槛。

## 建议的私有项目结构

位置由使用者指定或选择当前私有工作区；若当前是公开技能仓库，先确认另一个私有目录。

- originals/：原始材料或其本地引用，不修改原件。
- markdown/：逐份转换件。
- source-index.md：资料清单、转换覆盖与缺口。
- state.md：目标、当前阶段、确认记录、纠偏、下一步。
- facts.md：时间线、责任范围、事实冲突及采用口径。
- evidence.md：能力或价值主张、证据、反例和边界。
- deliverables/：摘要、画像和所选应用成果。

如果环境不支持文件写入，在对话中维护同样的简明记录，说明无法保证跨会话持久化，提供可复制的交接摘要。不要声称已保存。

## 单份Markdown转换件头部

- 资料编号：
- 原始文件名或消息来源：
- 材料时间范围：
- 转换状态：完整 / 部分 / 失败
- 已覆盖：
- 未覆盖及原因：
- 原件定位方式：

下方按页、幻灯片或工作表保留原始内容。图像转写、OCR不确定项和助手描述单独标识。不要将摘要或分析混入原始文本。缺少日期时写“文档中未提供”。

## 结论状态

资料记载 / 用户回顾确认 / 分析解释 / 发展假设 / 未知。状态可以并存，例如用户确认的经历仍可能缺少统计口径。不要将“用户确认”提升为外部审计验证。
